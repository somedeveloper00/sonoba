# Sonoba

![Demo showing text on the screen being replaced by the translation](docs/demo.webp)

This English version was translated from the Japanese README by PLaMo 3 Translate 2B, the model this app uses, and then corrected where it was wrong.

This is a tray app for Windows. It performs OCR on any area of the screen, replacing text with translations. You can choose from Japanese, easy Japanese, English, Korean, or Chinese as the target. Like Google Translate's image translation, it overlays the translation on top of the original text. All processing is completed entirely on your PC.

**[Download Sonoba (zip)](https://github.com/paisu-supai/sonoba/releases/latest/download/sonoba.zip)** (for Windows 11, 72MB, always the latest version). Previous versions and changes are in [Releases](https://github.com/paisu-supai/sonoba/releases).

Built with PLaMo.

## Getting started

The supported OS is Windows 11. No installation is required. The Visual C++ runtime is included in the zip file, so it works without installing it separately. Extract the zip file to your preferred folder and launch `sonoba.exe`. The first time you run it, a guide opens: select the display language and a translation model. The guide offers the light and standard sizes; larger models can be downloaded later from Model in the settings. If you choose PLaMo 3 Translate, the guide asks you to agree to the PLaMo Community License before the download, and PLaMo 3 Translate does not translate until you agree. Hy-MT2 needs no agreement.

Settings and models are saved in the `data` folder next to the exe. Deleting the entire folder will also delete the app. The folder for translation models can be changed in the settings. To update, overwrite the folder with the contents of a new zip file. If you place the app in a location it cannot write to, such as Program Files, they are saved in the `Sonoba` folders in `%APPDATA%` and `%LOCALAPPDATA%`. If you are using auto-start, disable this in the settings before deleting the folder.

Since this is a downloaded file, you may encounter a SmartScreen warning upon the first launch. Select "Run anyway" under "More info," or check "Unblock" in the zip properties before extracting. On PCs where Smart App Control is enabled, this step is required before extraction.

## How to Use

| Key | Action |
| --- | --- |
| Ctrl+Alt+T | Select a region and translate once. |
| Ctrl+Alt+R | Select a region and continue translating in real time. To stop, press Ctrl+Alt+X or press it twice in succession. |
| Ctrl+Alt+X | Stop translating and delete the translation |
| Ctrl+Alt+Q | View the original only while pressing |
| Ctrl+Alt+C | Copy the translation to the clipboard. The result appears next to the cursor. |

You can change the keys in the settings. The middle and side mouse buttons can also be assigned. Each key can be reverted to its default or disabled. Hotkeys are only disabled while a key is selected in the settings screen.

Select a region by dragging. While dragging, a green line appears outside the region. Clicking without dragging selects the entire window within a white frame. You can undo the selection by pressing Esc or right-clicking outside the regions. Once undone, the previous translation will continue. While you select, the regions being translated show a green line even when "Green border" is off in the settings. Right-click inside one to remove just that region; the selection stays open so you can keep choosing.

While selecting a region, a bar appears at the top of the screen. You can toggle the source, target, and live settings on or off here.

While translating, press Ctrl+Alt+T or Ctrl+Alt+R again, then drag while holding Shift to add a region. Clicking a window while holding Shift adds that whole window. You can simultaneously translate distant areas or other apps, such as subtitles and the chat field, or a game and a comment viewer. If you don't hold Shift, the current translation will stop and be replaced by the new region.

Each region operates in the mode selected for that selection. When "live" is on in the bar, the selected region is translated in real time; when off, the selected region is translated as a one-shot translation. For one-shot translations, only the translation for that specific region disappears when the page changes. When multiple regions are selected, they will not move with the window.

You can stop both the hotkey and translation using "Pause" from the system tray's right-click menu. Use this when it conflicts with game keys. Live translation will resume from where it left off once restarted.

Press the same hotkey again on the region selection screen to translate the same region as before. To re-translate after turning a page, simply press Ctrl+Alt+T twice.

Translations are overlaid on top of the original text, paragraph by paragraph, with font size, background color, text color, and boldness matched to the original. Labels in one row in the same colors, such as a menu bar or the boxes of a diagram, share one font size and weight. Labels stacked three or more in a column in the same colors, such as a settings screen's headings, share one font size when their sizes are close. When the translation is long, if it spans one line, it expands into the empty space on the right, and a paragraph into the empty space below; if that is still insufficient, the letters are made a little narrower, and only then is the text reduced in size. Japanese translations do not break a line inside a run of katakana, kanji, or Latin letters, and particles and okurigana stay on the line of the word before them. Non-text elements, such as icons, input field borders, and images, remain visible. For text over photos or gradients, only the text is erased with the surrounding color, and the translated text is overlaid with a border. In live mode, when the picture behind a translation changes while the text stays, the letters are painted out again from the screen as it is now. A line read over a photo or picture with little confidence is taken for a pattern, such as a lattice, and not translated. Elements whose translation does not change, such as numbers or code, are not replaced.

The selected region is linked to the window below it. Moving the window moves the translation along; resizing it retranslates; and minimizing it hides it. For one-shot translations, the text automatically disappears when the region's screen changes significantly.

The active window remains unchanged, as neither the selection nor the translation takes keyboard focus. Clicking or scrolling will move through the translation to reach the window below.

To show translations in screen sharing and recordings, turn on "Show live translations in screen sharing and recordings" in the settings. When the region is inside one window, translations then appear when the whole screen is shared or recorded. Regions added with Shift appear too, as long as each lies inside one window. To share a single window, pick "Sonoba for sharing - program name" (for example "Sonoba for sharing - chrome") instead of the original window. It appears in the taskbar once a translation starts, and shows the original window with the translations over it. There is one for each window with a region in it, so a game and a comment viewer can be captured separately, each showing only the translations of its own regions. It sits off the screen, so it never gets in the way.

- In Discord, picking this window shares no sound from the original app. To share the sound too, share the whole screen.
- In OBS's Window Capture, set Capture Method to "Windows 10 (1903 and up)". BitBlt shows it black.
- A minimized share window shows nothing. When the translation stops, it keeps showing the last translated window.
- When another window is brought in front of the original, the translations on screen go behind it. "Sonoba for sharing" still shows them all.
- With two windows of the same program, the second name ends in (2).
- A region across several windows, or on the desktop, is read from the screen as it is, so its translations appear in no share. If one of the regions added with Shift is like that, all of them are. "Sonoba for sharing" keeps showing the previous window without translations. It never shows the desktop.

## Settings

Double-click the system tray icon to open Settings. The Settings screen is displayed using WebView2, which comes standard with Windows 11.

- Source and target: Same settings as the bar used to select the region
- Style: Automatic, polite, plain. Auto matches the tone of the original. Only with PLaMo 3 Translate.
- Glossary: A list of words for which you want a fixed translation. It is used only when the word appears in the original text.
- Languages to read: Korean comes installed. Russian, Arabic, Thai, Hindi, Tamil and Telugu become readable once chosen and downloaded. Each can be deleted
- Translation model: Select, download, delete, load, unload, change the folder
- Execution Method: Automatic, GPU Only, CPU Only
- GPU Memory Limit: When set to Automatic, select the maximum GPU memory used by the translation engine.
- CPU Threads: When set to Auto, the number of performance cores is used. You can reduce this to your preferred number.
- Hotkeys: Keys for each of the five operations. Each key can be reset or disabled.
- Green border: Displays a thin line outside the translation region. For full-screen windows, it displays an inner line. You can also display a thick line for a brief moment when translation is complete. Both are disabled by default.
- Screen sharing and recordings: Live translations also appear in Discord or Meet screen sharing and in OBS recordings. Works only when the region is inside one window. Also brings up "Sonoba for sharing - program name" for each window with a region in it, for sharing a single window. Disabled by default.
- Translation font, bold, strength: Lowering the strength makes the original screen visible through.
- History: A list of recent translations with their original text. Translations that come on screen while it is open appear at the top, again each time a line comes back on screen. Also opens from "History" in the system tray's right-click menu. Search and copy available. Stored only in memory and disappears when the app is closed. Can also be turned off.
- Autostart: Starts when Windows boots. Disabled by default. When enabled, it writes the exe location under the name `Sonoba` to the registry at `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, and upon signing in, it starts while remaining resident in the system tray. No administrator privileges are required; it only affects your own account. Turning this off removes this value. When using the folder where the zip file was extracted, this is the only value written outside the folder. If you move the folder, turn it off and then back on again.
- Display language: Japanese or English. Set to match Windows language the first time.

The default "Auto" runs the portion in GPU memory on the GPU and the remainder on the CPU. If there is enough free space, everything runs on the GPU; on PCs without a GPU, it runs solely on the CPU. When GPU memory is low, switching to the lighter 0.8B option will make it run faster.

There is no RAM limit. Since RAM usage is determined by model size and the amount of data loaded onto the GPU, you can reduce usage by choosing a lighter model or increasing the amount of data loaded onto the GPU.

Launching the app again will open the settings for the running instance. The `sonoba.log` file in the `data` folder records when the app started and why it ended, including the cause if it crashes unexpectedly.

## Supported Languages

The system can read Latin-script languages (such as English, French, German, and Spanish), Chinese, Japanese and Korean. The Korean OCR model (13MB) comes in the zip.

The following languages become readable once their OCR model (8MB each) is downloaded under "Languages to read" in the settings, and are then translated automatically like the others.

- Russian, Ukrainian, Bulgarian, Kazakh and others (Cyrillic)
- Arabic, Persian, Urdu and others
- Thai
- Hindi, Marathi, Nepali and others (Devanagari)
- Tamil
- Telugu

Small text (9pt) is misread more often. Hindi, Tamil and Telugu had some letters misread even at 15pt. Ukrainian is among the languages Hy-MT2 supports, but not among those PLaMo 3 Translate supports. Greek is left out, as neither translation model supports it.

It does not touch characters written in the target language. For example, if the target is "easy Japanese," it translates only the foreign language into easy Japanese, leaving the Japanese text on the screen as is. If the source is set to "Japanese too," the Japanese text on the screen is also rewritten into easy Japanese. Easy Japanese is a specification not found in the model card (`ja(easy)`) and is used by the model template and the PFN CLI.

When the target language is English, sentences containing only Latin characters are treated as English and are not translated.

## Model

| Model | Size | Notes |
| --- | --- | --- |
| PLaMo 3 Translate 0.8B | 0.6GB | Lightweight. About twice as fast as 2B, but more mistranslations. |
| PLaMo 3 Translate 2B | 1.8GB | Standard |
| PLaMo 3 Translate 8B | 5.3GB | High quality |
| PLaMo 3 Translate 31B | 19.5GB | Highest Quality |
| Hy-MT2 1.8B Light | 0.8GB | The standard one made smaller by unsloth, at 3 bits (UD-IQ3_XXS). About 1.4GB of memory. Translations are a little worse than the standard one. |
| Hy-MT2 1.8B Standard | 1.1GB | Tencent's model. Apache License 2.0, so it needs no agreement and can be used at work. About as fast as 2B, about 1.7GB of GPU memory. The style setting does not apply. |

Other models can also be used. Placing GGUF files in the model folder (`data\models` by default) will make them appear in the settings list. The kind of a model is told from the name written inside the GGUF file, and from the filename where that does not say. A PLaMo 3 Translate file is treated as PLaMo 3 Translate even when another app has stored it under a different name, and its license is asked for. The Hy-MT2 files Tencent distributes carry only "1.8B" as their name inside, so a file is treated as Hy-MT2 when its filename contains `Hy-MT`, and is asked in the words of the model card. Any other model is asked to translate through its own chat template.

The model folder can be changed with "Choose folder" under Model in the settings. A folder shared with other apps, or one on another drive, can be chosen. The GGUF files in the chosen folder appear in the settings list, and downloads are saved there. Changing the folder neither moves nor deletes the models in the old one. The OCR models stay in `data\models` whichever folder is chosen.

If you cancel the download, files left unfinished will be retained, and the next download will pick up from where they left off. If you no longer need them, you can delete them using "Delete."

The OCR model is unloaded after 60 seconds without use, and the translation engine is stopped after 15 minutes without use. Since unloading means stopping the engine, both the memory and GPU memory are completely freed up.

The differences between the execution method and the engine are as follows (translation of 10 paragraphs, 4 simultaneous).

| Setup | Time | RAM | GPU memory |
| --- | --- | --- | --- |
| Automatic (Default, all GPU on this PC) | 0.68 seconds | 360MB | 2.15GB |
| Automatic, GPU memory limit 1.5GB | 3.8 seconds | 1.0GB | 1.5GB |

The more layers you pass to the CPU, the slower it becomes, so use the GPU memory limit only when memory is short. Setting a limit also extends the loading time by about 3 seconds to account for the allocation calculation.

## How It Works

- The screen is captured using GDI's BitBlt. A separate thread scans the screen every 0.033 seconds and passes any changes to OCR. Since it can detect changes even during OCR, old translations are quickly cleared. With several regions, each is read on its own, and only the regions whose picture changed are read again. When a list has only moved up or down (a chat taking a new comment, for example), the translations move with it and only the new lines are translated.
- With the screen sharing setting on, each region is read from its window with PrintWindow. That leaves the overlay out of what OCR reads, so the translations no longer need hiding from recordings. A window lying on top of the region is not read; the text of the window underneath is. Every 0.05 seconds the translations on screen are cut to the shape of the windows in front.
- "Sonoba for sharing" is a window holding DWM thumbnails of the original window and of a copy of the overlay on top of it. The copy sits off the screen and is never cut or hidden from capture. Each region in the window gets its own thumbnail of just that part of the copy. DWM draws it; Sonoba only matches its position and size every 0.05 seconds.
- OCR is executed on the CPU using PP-OCRv6 small via rten. The model is embedded in the exe. When per-language models (PP-OCRv5) such as the Korean one are in `data\models`, only lines read with low confidence, and lines where far too few letters were read for their width, are also read with those models. If one of them reads letters of its own script, its reading is used. The models are tried starting from the language read last, stopping at a confident reading. For Arabic, the letters the model gives from left to right are put back in right-to-left order. The number of threads is adjusted to match the number of performance cores on the PC. A blank gap about one and a half letters wide splits the detection frame, as between menu items or table cells, and each piece is read on its own. Where a bright picture behind leaves no blank gap, a line is also split where the letters read lie more than four times their usual spacing apart. A line read with an accented letter is read again with a little more room above and below, and the surer reading is used: an English l close to the frame's edge can read as an accented i. The ink within the detection frame is examined line by line to determine the character-only region, background color, text color, and boldness. Letters with an outline or glow are sized by the letters alone. Over a photo or a drawing, only pixels close to the text color count toward the height, and small specks apart from the letters do not. Wrapped lines join the line just above them in the same column, so columns side by side each make their own paragraphs. A line that lines up with the one above at neither its left edge, its middle nor its right edge is not joined to it, so a game's menu bar does not run into the dialogue under it. A short last line with no letter reaching below the line, such as g or y, is compared with the line above by the font size worked out from its letters, not by the height of its frame.
- Translation is requested via HTTP by launching llama-server. Paragraphs are grouped into about 240 characters, one paragraph per line, sent four at a time, and displayed as each line is completed. The grouped paragraphs form the context, and the original text of the preceding group is also provided for reference. Short paragraphs of up to three words, such as labels, go one at a time: grouped, the model may join or reorder them, and a translation can land in the wrong place. Each goes with the labels near it as context: alone, "Exit" becomes 出口 (a way out), but beside the other items of a menu, 終了 (quit).
- Window movement is detected via WinEvent, and the translation is moved without performing OCR.
- The overlay is the frontmost window with a transparent color.

## Limits

- By default, live translations will not appear in screenshots or recordings. This is to prevent OCR from reading its own translations. With "Show live translations in screen sharing and recordings" turned on in the settings, they do appear when the region is inside one window. One-shot translations will appear, though they may occasionally fail to do so. When multiple regions are selected, the one-shot translation region will also not appear.
- In live mode, text over photos or gradients is covered by a solid-colored square.
- Vertically written and rotated text cannot be read.
- Regions where the long side exceeds 1,600 pixels are scaled down before being read, making small characters harder to read. When there are multiple regions, each is measured on its own.
- In one-shot translations, the text disappears if 8% or more of the pixels change. It may remain with slight scrolling. Use live mode to make it follow the screen.
- Exclusive full-screen games and copy-protected videos are not supported.

## Build

Rust (MSVC) is required.

```bash
cargo build --release
```

The app looks for the translation engine at `engine\llama-server.exe` next to the exe file; if it's not found, it uses the one bundled with Ollama. The following command creates the distribution zip. It retrieves and includes the official build (Vulkan version) of llama.cpp, and puts the Korean OCR model (`models\korean_PP-OCRv5_mobile_rec.onnx`) in `data\models`.

```bash
powershell -ExecutionPolicy Bypass -File scripts/package.ps1
```

To check the display without touching the screen, draw the translation on the image and save it.

```bash
RENDER_IN=in.png RENDER_OUT=out.png cargo test render_picture -- --ignored --nocapture
```

The test of the per-language OCR models runs on a folder holding the models downloaded from the settings.

```bash
OCR_MODELS=data/models cargo test reads_the_scripts_that_come_as_downloads -- --ignored --nocapture
```
